      Settings

      Where "Open in Claude" goes

      You can switch per email in the card. Links pre-fill the prompt; Claude never sends it until you press Enter.

      Terminal links need a one-time setup: run claude once and send any prompt, so your system knows how to open claude-cli:// links.

      The Claude app asks you to confirm an SSH connection before it connects. Keys and passwords are never put in links.

      Default mode and permissions

      Links can't choose a mode, so Claude Code reads it from its own settings file. Add this once to %USERPROFILE%\.claude\settings.json (Windows) or ~/.claude/settings.json (macOS/Linux), merging it with anything already there. It applies to every new Claude Code session, not only ones started from email. Plan mode means Claude can't edit files until you approve its plan.

      Approvers
      
      
      
        Let another person approve your plans, or approve plans for others. An approval is signed in the approver's own
        browser, so Mail2Code can check that it really came from them and is for exactly that plan version. Requests and
        replies travel as ordinary Gmail emails; the wording of an email never counts, only the signed data in it.

        Stored email text
        
      
        
        Tasks keep a copy of the captured email text so the brief can be rebuilt. After a task closes (completed,
        cancelled, rejected or failed) that copy is deleted after the period below. Titles, Gmail links and history
        are kept. Deletion happens when the browser starts or when you open an extension page.
